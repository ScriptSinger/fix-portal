# Учёт изображений контента

`images` хранит диск, путь и прежний URL файла. `imageables` связывает изображение с
моделью, записью и полем (`content`, `description`, `text`). Статьи, вопросы,
комментарии и ответы синхронизируют связи в транзакции сохранения. HTML остаётся
форматом отображения. Публичные формы продолжают проверять принадлежность загрузок
через MessageBody; ID из произвольного HTML не является основанием для привязки.

TinyMCE регистрирует загрузку сразу, включая файлы из несохранённых форм.
Telegram сохраняет метаданные в существующей транзакции принятия публикации.
Аватары, миниатюры и файлы прошивок сохраняют свои отдельные жизненные циклы.

## Развёртывание

1. Остановить запись: maintenance mode, остановить queue и scheduler.
2. Выполнить `php artisan migrate --force`.
3. Выполнить `php artisan images:index --activate`.
4. Вернуть сайт, queue и scheduler в работу.

Команда повторно запускаема, регистрирует файлы `galleries/content` на media-диске
и строит связи существующего контента. Файлы не перемещаются и не удаляются.
При ошибке обхода хранилища или базы активация не выполняется. Для только индексации
используйте `images:index` без `--activate`.

До первой успешной активации сохраняется проверка ссылок через HTML для совместимости
со старой базой. После активации очистка проверяет `imageables`, без LIKE по текстам.
`images:prune-orphans` выбирает старые записи без связей, включая загрузки TinyMCE.
Обнаруженные старые файлы получают новую дату регистрации и обычную суточную паузу.

Массовые SQL update/delete обходят модельную синхронизацию. Команды изменения HTML
должны сохранять модель либо явно вызывать ImageRegistry::sync в транзакции.
Каскадное удаление пользователей и восстановление очистки после ошибок хранилища
относятся к следующему этапу; этот реестр их сам по себе не заменяет.
